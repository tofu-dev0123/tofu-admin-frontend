# ルール: コンポーネントとロジックの分離

コンポーネントを書く・直すときに従う。本プロジェクトの基本アーキテクチャ。

## 原則

**コンポーネントにロジックを書かない。ロジックはカスタムフックに切り出す。**

コンポーネント（`.tsx`）は「見た目」と「フックから受け取った値・ハンドラの配線」に専念する。状態管理・データ取得・イベント処理・副作用・分岐計算は `src/hooks/admin/<feature>/use*.ts` に置く。

## コンポーネントに書いてよいもの / いけないもの

| 書いてよい                                        | フックに出す                          |
| ------------------------------------------------- | ------------------------------------- |
| JSX とレイアウト                                  | `useState` / `useReducer` などの状態  |
| フック呼び出しと返り値の分配                      | `useEffect` などの副作用              |
| 単純な表示用の条件分岐（`isPreview ? ... : ...`） | API 呼び出し・データ整形              |
| `className` の組み立て（`cn`）                    | イベントハンドラの実装（`handleXxx`） |
| 子へ props を渡す配線                             | バリデーション・ビジネスロジック      |

## 進め方

1. 画面・機能の状態とふるまいを `use<Feature>()`（または複数の小さなフック）に実装し、必要な値とハンドラを返す。
2. コンポーネントはそのフックを呼び、返り値を JSX に流し込むだけにする。
3. ハンドラ名は `handleXxx`、ロジックの単位でフックを分割する（例: `useHome` が `useSummary` / `usePostList` を束ねる）。

実例: `src/hooks/admin/home/useHome.ts` と対応する画面コンポーネント。

関連: フック実装の詳細は [[react-hooks]]、状態の置き場所は [[state-management]]。
